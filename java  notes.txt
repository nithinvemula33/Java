================ Introduction to Java ==================
  
  Java is a high-level, object-oriented programming language developed by James Gosling at Sun Microsystems in 1991.
It was released in 1995 and is known for its platform independence through the Java Virtual Machine (JVM).

C/C++ ---> Platform dependent langs.
JAVA  ---> Platform independent lang.

C --> Procedure Oriented lang.
C++ --> C + class.
C++ --> object oriented lang.

#--Procedure Oriented lang--

    If a same task is given 10 times , executes ten individual times. Therefore time complexity increses .

#--object oriented lang--

    It takes a class and executes ten similar tasks only once. Therefore time complexity decreses.

================ JVM(Java Virtual Machine) ================

    Java Virtual Machine is a virtual machine that executes Java bytecode and enables Java programs to run on different operating systems without modification.

#--------- Architecture of JVM ------------

1. Class Loader Subsystem

    Loads .class (bytecode) files into memory.

Performs:

    Loading – Reads class files.
    Linking – Verifies and prepares classes.
    Initialization – Initializes static variables and blocks.

2. Runtime Data Areas

    These are the memory areas used by the JVM during execution.

# Method Area

-> Shared among all threads.

Stores:

-> Class metadata
-> Method information
-> Static variables
-> Constant pool

# Heap

-> Largest memory area.
-> Stores all objects and arrays.
-> Shared by all threads.
-> Garbage Collector mainly works here.

# Java Stacks

-> Each thread has its own stack.

Stores:

-> Local variables
-> Method calls
-> Partial results

# PC Registers (Program Counter)

-> One per thread.
-> Stores the address of the current instruction being executed.

# Native Method Stacks

    Used when Java calls non-Java code (e.g., C/C++ libraries).

3. Execution Engine

    The Execution Engine runs the bytecode.

# Interpreter

-> Reads bytecode line by line.
-> Executes instructions one at a time.
-> Slower because it repeatedly interprets code.

# JIT (Just-In-Time) Compiler

-> Identifies frequently executed code ("hot spots").
-> Compiles them into native machine code.
-> Improves performance significantly.

4. Native Method Interface (JNI)

    JNI (Java Native Interface) allows Java programs to interact with native applications written in:

-> C
-> C++
-> Assembly

5. Native Method Libraries

    These are platform-specific libraries:

-> .dll files on Windows
-> .so files on Linux

    JNI uses these libraries when Java calls native code.

6. Operating System

-> The JVM ultimately runs on the operating system.
-> Native machine code generated by the JIT Compiler is executed by the OS.

# Complete flow.

 ## Summary
    
    JVM Architecture consists of the Class Loader Subsystem, Runtime Data Areas (Method Area, Heap, Java Stack, PC Register, Native Method Stack),
Execution Engine (Interpreter and JIT Compiler), Native Method Interface (JNI), and Native Method Libraries. The Class Loader loads bytecode, 
Runtime Data Areas store program data, and the Execution Engine executes the bytecode to run Java applications.
